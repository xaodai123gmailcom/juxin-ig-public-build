# Public Windows verification

This workflow verifies a real, exact GitHub source checkout in the designated public repository. It runs six early native fixtures and all 36 required early backend groups, preserves their runner-local evidence, checks out the same commit into a fresh tree, and invokes the original full Windows build with `-BrowserMode installed-chrome`. No release gate is replaced by a mocked test.

Before the long regression suite, the focused saturation check repeats the previously failing offline fixture. Pure wiring contracts verify the actual public workflow, wrapper and original build chain. The existing native logging probe also runs under PowerShell 7 and must restore its native exit preference.

Before dependencies, both base and project Python run the retained-handle descendant regression immediately before the original descendant precheck. The controlled fixture retains the child's `Popen` during a bounded acknowledgment handshake, verifies its exact held handle belongs to the actual private job, and checks that child and parent remain unsignaled before acknowledgment. Source-verified Windows run [37528829614](https://github.com/xaodai123gmailcom/juxin-ig-public-build/actions/runs/37528829614), commit `64af2206bda597870b8d56ddc892b1d7c590dd5e`, established that this retained child was unsignaled both after accounting first reached zero and immediately after supervision returned, then became signaled within the original cleanup budget. That evidence establishes the ordering for this controlled trial; it does not establish every cause of the earlier fixture's failure.

Both descendant tests now require independent held-process signaling to be observed within the existing two-second cleanup budget, replacing the original zero-time assertion after joining the supervision worker. A test-only containment records the deadline immediately before the unchanged `TerminateJobObject` call. Native API time, return and join work all consume this same budget. The original fixture retains its outcome, job-empty and 15-second join assertions; the controlled fixture also retains acquisition, exact handle/job/root identity, full cleanup receipt and observation chronology checks. Only the remaining deadline may be used for one bounded confirmation wait, with no additional two-second allowance, sleep or retries. A signal observed exactly at the deadline passes; a first signal observed later fails. An unsignaled sample with zero or sub-millisecond residual fails conservatively. The two former diagnostic failure classes for verified in-budget signals are removed; rejected evidence, missing in-budget signaling and actual Windows wait failures remain fixed assertion categories. Public fields are unchanged and the exception enum contains 26 fixed reviewed categories, including the installed-recovery phase categories described below. Production supervision, every other native case, execution/drain/termination/worker/outer limits of 10/.5/2/15/60 seconds, original full source/build/installed gates and base/venv precheck wiring remain unchanged.

The early Unicode source gate creates a fresh source copy and Python environment under a non-ASCII path. It verifies the original OpenVINO DLL and model assets belong to that copy, exercises the real four-model classifier and gender branch, and requires the native DLL to load from its own fresh ASCII cache. After the original full build is validated, a byte-checked copy of the already-frozen Core runs under a Unicode path with separate layout, inference and service checks. This is a copied-runtime check, not another full application build. The outer Unicode source and copied-frozen checks are bounded at 3600 and 900 seconds; existing inner inference/service deadlines remain in force. These actual runtime checks execute only on the Windows runner.

The contracts phase includes an isolated import/CLI preflight before dependencies and full build. It calls the original verifier's frozen-mode help through the same fixed loader used for both frozen layout checks. The loader verifies and compiles captured source bytes for exactly five existing files: the verifier, its model-download sibling, and the app package/privacy/bootstrap support files. Both package search paths are empty; valid cached bytecode cannot replace those captured source snapshots. It does not make the working directory, PYTHONPATH, or the scripts directory importable. It restores the original import path and removes only the module objects it inserted, including on failure. Fixed original/copy child modes derive their manifest and Core paths from the sealed checkout and exact owned run directory and recheck manifest equality. The preflight blocks OpenVINO/telemetry package imports and matching native-library loads, and must exit through help before any layout or inference work. It establishes import/CLI compatibility only; real copied-runtime layout, inference, service and installed checks remain mandatory.

The separate installed stage silently installs the newly built NSIS product into a fresh runner-local destination. It verifies installed native resources and inference, actual frozen Core behavior, scale and upgrade invariants, and the actual installed desktop's authenticated recovery API. Independent receipt validators check source identity, runtime identity, case coverage, screenshot hashes, installed EXE/app.asar hashes, prior upgrade evidence, and retained early receipts. All raw evidence, screenshots, model files, dependencies, profiles, source copies, logs, and binaries remain on the runner.

If the installed recovery verifier fails, its full traceback stays in its existing runner-local combined log. The already-failed installed stage also feeds that one fixed child-log path through the existing bounded diagnostic parser. Only the existing source-sealed relative locations and fixed observed exception categories can reach the public summary; exception messages, absolute paths, full tracebacks and application data remain local. Missing or unreadable logs and parser failures retain the failed gate. This diagnostic capture does not relax proof assertions, public fields, file counts or export bounds.

Installed renderer discovery dispatches Playwright protocol events before inspecting cached contexts, pages and URLs; a Python sleep alone cannot deliver a delayed page or navigation event. Selection still requires exactly one main renderer at the selected installed app.asar path and the real collectorCore.request preload API. It does not evaluate account pages or substitute the first tab. Observed debugger, renderer-target, preload, trusted-API-readiness, API-exercise, shutdown, process-exit and overall deadline failures use nine fixed InstalledRecovery exception categories, without exporting page URLs or exception messages. These categories identify an observed verifier phase, not an inferred application root cause.

The launch uses a finite 420-second overall watchdog and separate maximum phase budgets: debugger 30 seconds, renderer discovery 210 seconds (the product's 180-second first frozen-Core startup allowance plus 30 seconds for window/navigation), preload 15 seconds, trusted API readiness 30 seconds, recovery API exercise 60 seconds, and graceful shutdown 60 seconds (covering the product's 45-second Core stop grace plus 5-second forced stop). Every phase is clipped to the remaining overall budget. The outer native wrapper allows 540 seconds for prelaunch work and bounded owned-process cleanup; it cannot substitute for a successful recovery receipt. The application and its startup/shutdown policy are unchanged. Delayed target/navigation, wrong or duplicate target, missing preload, process exit, finite deadlines and cleanup are covered by isolated contract tests, now also run in the contracts phase before expensive early/build work. These additive checks do not replace the original source suite or actual installed acceptance.

Only three newly constructed, size-bounded JSON summaries can be uploaded: `run-summary.json`, `source-build-proof.json`, and `installed-acceptance-proof.json`. Each has the real run identity and the current schema-2 public source identity. Passed build/installed stages include fresh binary hashes; interrupted, failed, and not-run stages retain those distinct statuses. Failure diagnostics separate source-sealed test names from exact unittest failure headers and generic log context. Other allowed fields are fixed gate names, process outcomes, exit codes, sealed relative source locations, fixed allowlisted observed exception categories, and explicit omission counts. Exception categories are observations from bounded log tails or exact allowlisted built-in parent exception types, not automatic root-cause findings. Parent traceback evidence includes only manifest-sealed relative file/line pairs; no messages, arguments, locals, function names, custom class names, causes or nested exception payloads are inspected. Parent and child observations are deduplicated before the existing caps, with truthful omission counts. No raw exception messages are exported. Diagnostic parsing cannot make a failed gate pass. The three summaries are evidence, not downloadable installers.

Passed installed acceptance also includes a bounded CRT inventory with selected installed file hashes, numeric version observations, fixed notice hashes and source-byte comparisons. Unreviewed layouts are explicitly marked incomplete without exposing unexpected filenames. The inventory digest binds its observations to the installed-stage result; an incomplete inventory does not bind unknown-file contents. Unsafe links, malformed evidence and mismatched known bytes still fail closed. These observations do not establish redistribution rights, and no binary publication path is enabled.

Before dependency imports, raw ASCII `0` is written and read back at the actual Windows Local AppData telemetry file, whose location is verified through the Windows shell API. Every child gate rechecks it. The wrapper preserves the profile environment, canonicalizes only TEMP/TMP, removes credential variables from build children, disables pip configuration-file loading, explicitly selects official PyPI and npm registries, and gives npm empty per-job user/global configuration. Existing Microsoft-signed VC runtime and Google-signed installed Chrome are checked before the build; missing prerequisites fail closed. The workflow does not install or repair system prerequisites, request elevation, or change execution policy or security settings.

## Contract-suite coverage mapping

Posting, Pexels, crop, and material-publishing execution are retired. Their native fixtures, raw proof requirements, and crop oracle are removed. Native collection recovery is schema 2: it proves the production shell has only retained routes, hidden paused collection lookup and exact stop targets, cancellation, stale/live blockers, repeated-click collapse, separate cleanup, and the cleaned window becoming available. A start intent is always rejected. Native visible screenshots, trusted input, timing, source hashes, and fail-closed runtime identity checks remain mandatory.

- `test-r63-native-proof.py` retains its strict nurture cleanup oracle: complete scenarios and observations, Windows identity, current source/compiled-host hashes, no external activity, and valid painted screenshots
- `test-r63-upgrade-proof.py` retains strict old-database, frozen executable, chronology, history, and admission checks; the removed prepared publishing state is covered by the recoverable-retirement contract rather than restarted
- `test-r64-recovery-ui-proof.py` checks every schema-2 field, collection/nurture scenario, production source, exact stop target/version, timing, trusted input, and screenshot; removed or unexpected posting start intents fail
- `test_public_ci.py` checks the exact retained early fixture and backend-group lists, real-browser requirements, failure aggregation, final-seed timing, fresh same-commit checkout ordering, single NSIS/sidecar identity, retained early hashes/equality, late groups, per-case/teardown watchdogs, installed frozen route rejection, and actual installed desktop recovery
- `test_public_build_contract.py` mutates the mandatory workflow/build chain and verifies required calls cannot be missing, optional, reordered, or ignored
- Public-export negative tests retain exactly three bounded JSON files and reject credentials, write-capable/unpinned actions, wildcard/binary/log/screenshot uploads, stale stage/source/binary identity, false success, non-allowlisted diagnostics, and oversized exports

The installed frozen Core must return HTTP 404 for every retired posting/Pexels endpoint, and the installed desktop recovery check independently exercises its guarded IPC boundary. Work-report verification now requires the four retained card totals. Collection, nurture, lease ownership, hidden paused collection recovery, source identity, Unicode/isolated imports, native model inference, scale/upgrades, NSIS, and actual installed runtime gates remain required. The R10 bounded runner-local failure diagnostic and binary-publication hold are unchanged.

These local static/mocked contract suites establish only their assertions. They do not establish actual Windows execution, native UI, frozen inference, or installed product acceptance. Those mandatory product gates execute only on the hosted Windows runner. The example upgrade receipt is explicitly synthetic and non-executable.
