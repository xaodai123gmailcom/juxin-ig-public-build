## Source controls

`CI_SOURCE_PROVENANCE.json` contains `schema`, `mode`, `representation`,
`repository` (`full_name`, `id`, `owner_id`), `product_version`, `source_revision`
and `source_manifest_sha256`. Product version is `3.0.4`; source revision is
`stability-r94`. The manifest digest is calculated from the exact final bytes of
`SOURCE_SHA256.json` after all reviewed public changes are integrated.

`SOURCE_SHA256.json` lists every final tracked public source file except itself
and `CI_SOURCE_PROVENANCE.json`. Both excluded control files are independently
bound to their actual committed Git blob bytes. The controls cannot authenticate
themselves merely by agreeing with one another.

The public representation contains no archive ancestry, private local controls,
internal delivery reports, private repository history, credentials or user data.
Do not copy private manifests into it. A different representation requires its
own explicitly reviewed verification design.

## Verification

In the actual GitHub Actions checkout:

    python scripts/ci_source_binding.py --root .
    node scripts/verify_build_source.mjs

The verifier requires real Actions-provided identity, including `GITHUB_SHA`,
`GITHUB_REPOSITORY`, `GITHUB_REPOSITORY_ID` and `GITHUB_REPOSITORY_OWNER_ID`.
It compares HEAD, the stage-zero index, tracked paths/modes/blobs, raw on-disk
bytes and the source manifest. Missing or extra tracked source, dirty or staged
changes, untracked executable source, unsupported links, Git redirection and
identity mismatch fail closed. It does not fetch source or run filters to repair
the checkout. Required receipts recheck source identity; there is no production
cache or matching-SHA-only fallback.

Preserve `.gitattributes` and exact file bytes. Source modifications require a
reviewed new final manifest and commit; a previously valid receipt cannot bless
later edits. Build/dependency outputs are allowed only under the validator's
explicit output rules and do not become authenticated source by their location.

Local unmarked diagnostic fixtures cannot claim a source commit. Required public
receipts intentionally cannot be generated by manufacturing Actions environment
variables on another machine. Unit tests create temporary synthetic Git fixtures;
their synthetic context is test evidence only.

## What the receipt proves

A source receipt binds examined bytes to the actual checked-out commit and
supplied execution context. It is not proof of successful Windows compilation,
native UI, frozen Core, installed execution or any live service. Final acceptance
requires those independent same-source and same-installer reports, as described
in [release verification](../RELEASE_VERIFICATION.md).
