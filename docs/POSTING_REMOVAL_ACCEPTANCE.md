# Posting removal acceptance

This is a change in product scope, not a waiver for a failed posting recovery gate. Posting, Pexels configuration, posting scheduling/execution, crop workflows, posting navigation and posting report metrics are removed. Collection, nurture, account management, inventory, permanent collection deduplication and operational history remain supported.

## Required replacement evidence

- The selected installed desktop and its exact child frozen Core start against an independently preseeded, isolated historical database. Source tests alone cannot satisfy this gate.
- Removed posting and Pexels HTTP endpoints return 404, and the desktop bridge cannot admit posting requests. There are no compatibility aliases that execute retired actions.
- Legacy caption, material bytes and historical receipts are verified in a recoverable local archive before their safely idle associations leave active storage. The independent seed captures table, index and trigger topology before candidate startup and binds it into the input manifest. The oracle checks archived rows, schema topology and material hashes against that authority, rather than trusting success flags or redefining expectations from the post-migration database. Coordinated index/trigger loss in both active storage and a rehashed archive must fail. Archive verification failure must stop retirement.
- Active, held or uncertain historical ownership remains fenced. Another owner's lease is never deleted, reassigned or claimed merely because the feature was removed. No browser publishing code, automatic retry or external action may run.
- A hidden paused collection task is absent from the ordinary list but precisely locatable by its owner. Wrong-owner, stale-version, wrong-task and noninteger stop requests fail. A normal versioned stop preserves history, checkpoints, deduplication and dismissal; releasing the nurture hold requires a separate authoritative closed-window confirmation.
- Native collection recovery proves repeated-click collapsing, cancel-without-mutation, live-blocker refusal, stale-stop rejection, visible feedback and separate cleanup intent with current-source screenshots kept on the runner.

## Gates that stay mandatory

Source identity, exact GitHub Actions provenance, unchanged sealed source inputs, Unicode paths, isolated Python `-I` execution, owned-process cleanup, real browser collection and nurture, database upgrades, snapshot/history scale, exact report and CSV totals, models/OpenVINO/runtime checks, native UI, frozen Core, NSIS identity and the actual installed runtime remain required. A retired posting/crop fixture is removed only because its production feature is removed.

## Publication boundary

The public export remains exactly three bounded synthetic JSON files. Installers, raw logs, screenshots, credentials, account information, private data and archive content are not published. Binary distribution stays on hold. No full Windows pass is claimed until the real final-source workflow and installed gates finish successfully.
