# R6 合并报表与完整计数验证

## 页面范围

- 导航只保留一个“报表”，紧挨“历史”上方；旧 `#/data` 地址替换到 `#/reports`
- 上方以工作报表为主：日期/当日/当周/当月、统计卡、刷新、完整 CSV、两类审查报表均保留
- 统计卡保留采集、关注、分裂、新增四项；发帖统计、明细和 CSV 字段已移除，旧内容先验证可恢复本机归档
- 删除“窗口与账号明细”整个区块，包括原搜索框与明细表；没有删除底层记录
- 下方“数据概览”为辅助区，展开后独立读取原数据页的 8 个累计指标、任务状态汇总、每日完成记录（UTC）
- 累计数据明确标注不随上方日期变化；它的读取、失败或刷新不阻塞上方报表卡

## 查询修复

原报表先将全部历史采集证据（含大块 profile JSON）做窗口排序，再过滤所选日期。

R6 先用日期索引读取所选区间。汇总只保留账号身份，先跨任务结果、候选记录、排除记录去重，再使用身份索引排除在更早日期已经出现的账号。报表卡不读取 profile、review、executor JSON，也不读取其他不需要的报表指标。

分裂数量仍由永久完成事实和完成历史的首次完成代次共同决定。跨期重复、延迟回调、不同账号所有者及不同平台记录不会重新计数。完整 CSV 按需读取完整分组结果，不添加条数上限，不按屏幕可见部分截断。

SQLite 日期索引只用于粗范围检索。精确 UTC 时间键保护时区、DST、半开区间和微秒边界；旧 SQLite 将 `23:59:59.999999` 舍入到下一天的行为不会改变报表计数。普通区间内部记录不需要逐行调用 Python 日期解析。

每个响应的全部指标使用同一个 SQLite WAL 读快照。不使用有过期时间的报表缓存，因此刷新会读取最新已提交记录。旧日期、旧页面、旧导出的迟到响应不能覆盖当前页面或触发过期下载。

## 验证方法与范围

`backend/tests/test_work_report_performance_r6.py` 检查精确计数、所有者／平台隔离、
微秒边界、同一读快照、无条数截断和避免无关 payload 读取。发帖指标与行不得出现在当前报表。前端回归覆盖日期变化、完整 CSV、
迟到响应隔离和错误恢复。

使用 `scripts/benchmark_work_reports_r6.py` 在临时合成数据库上测量当前源码。
分别记录数据规模、区间内身份、首次／重复查询、完整 CSV、索引创建、内存和临时空间。
繁忙区间与完整导出仍需处理相关身份，不能承诺固定毫秒延迟。不得用删除、近似计数或
截断结果换取速度。本文件不记录旧构建的性能数字或测试通过数量。

Windows 原生 fixture 为 `desktop/tests/work-report-summary-r6.integration.cjs`，
检查合并导航、懒加载、等宽卡片、窄窗布局、完整数字、重复点击和过期导出阻断。
安装后报表 HTTP 与原生 UI 仍是独立必需门禁，静态或合成测试不能替代。

所有测试应使用隔离临时数据，不打开用户数据目录。只从对应实际运行的报告读取结果。
